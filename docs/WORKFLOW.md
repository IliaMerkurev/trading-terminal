# Рабочий процесс автономного прототипа

## Источник правды
PROJECT.md — продукт. AGENTS.md и AUTONOMOUS_RUN.md — правила текущего запуска. ADR — инженерные решения. Git — код и проверенные изменения. docs/STATUS.md — точка продолжения. docs/RUN_REPORT.md — факты и проверки. Ни один документ не является доказательством выполненного внешнего действия.

## Автономная итерация
Предпусковая проверка при владельце → автономное поручение → выбор следующей доступной задачи → реализация → целевые тесты → checkpoint → следующая задача без нового подтверждения. Большую цель дробить на маленькие изменения. Завершённый подпункт не завершает всю цель.

Один writer. Read-only review может дополнять тесты. Не создавать бесконечные расписания или массовые параллельные агенты. Длительный локальный запуск требует работающего клиента и среды; лимиты и подтверждения могут остановить его.

## Репозиторий
Публичный, как выбрал владелец. До запуска определить точный remote. Коммиты в рабочую ветку, push после проверки секретов и публикуемого содержимого, при необходимости draft PR. Автоматический merge в main, релиз и деплой не входят в запуск. Если публикация недоступна, продолжать локально без обхода разрешений. .gitignore не удаляет уже попавшие в историю данные.

## Задачи
На первом автономном запуске можно полностью работать с docs/TASKS.md. Linear подключать к работе лишь после реального чтения и отдельного разрешения записи в конкретный проект. Не создавать второй трекер в GitHub Issues. Отсутствие доступа не должно расходовать весь запуск на настройку интеграций.

После успешного переноса в разрешённый Linear проект статусы ведутся там, а TASKS.md хранит соответствие ключей. Не помечать пользовательскую приёмку автоматически выполненной.

## Возобновление
Перед дальнейшими действиями новая сессия читает AGENTS.md, PROJECT.md, AUTONOMOUS_RUN.md и STATUS.md, затем фактический Git status и следующий пункт. Не пересылать всю историю чата. Сохранять статус по мере работы, а не только в финальном сообщении.

## Готовность
Требования реализованы и проверены, команды воспроизводимы, допущения видны, незавершённое перечислено. Отчёт различает автоматические проверки и ожидающую приёмку владельца. GUI без расчётной интеграции не считается готовым продуктом. После готовой V1 остановиться, не переходить к AI/торговле/другим отложенным функциям.

Актуальные технические справки о разрешениях и длительных задачах — docs/PERMISSIONS.md. Этот файл заменяет неавтономный workflow v0.3; конкретные аккаунты и подключения здесь не объявлены настроенными.
